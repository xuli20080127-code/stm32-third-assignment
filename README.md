## 项目概述

本项目在第二次培训的三灯流水灯工程基础上，加入了按键控制、USART1 数据包通信、状态显示和串口反馈。

程序使用同一组状态变量保存流水灯信息，按键和串口都只修改这份状态，LED、OLED 和串口反馈都从这份状态获取数据：

```text
PA11/PA12外部中断 ──┐
                    ├──> 事件标志 ──> 主循环处理 ──> 统一状态
USART1接收中断 ─────┘                                  │
                                                       ├──> 三颗LED
                                                       ├──> OLED
                                                       └──> 串口反馈
```

主循环维护的主要状态包括：

```c
uint8_t lamp_running;       // 0：暂停；1：运行
uint8_t lamp_direction;     // 0：正向；1：反向
uint16_t lamp_step_ms;      // 相邻LED切换间隔
uint8_t lamp_led;           // 当前LED编号：0、1、2
```

OLED 显示的 LED 编号使用 `lamp_led + 1U`，因此屏幕上显示为 `1、2、3`。

## 硬件连接与引脚

三颗 LED 为低电平点亮，同一时刻只点亮其中一颗。

| 功能                | STM32引脚 | 说明          |
| ----------------- | ------- | ----------- |
| LED0              | PA4     | 低电平点亮       |
| LED1              | PA6     | 低电平点亮       |
| LED2              | PA7     | 低电平点亮       |
| 暂停/继续按键 `KEY_RUN` | PA11    | 内部上拉，下降沿中断  |
| 方向按键 `KEY_DIR`    | PA12    | 内部上拉，下降沿中断  |
| USART1 TX         | PA9     | 接USB-TTL的RX |
| USART1 RX         | PA10    | 接USB-TTL的TX |
| OLED SCL          | PB1     | 软件I²C时钟线    |
| OLED SDA          | PB0     | 软件I²C数据线    |

两个按键的另一端均连接 GND。按键松开时，内部上拉使引脚保持高电平；按下时引脚接到 GND，形成下降沿。

串口和 OLED 的接线如下：

```text
STM32 PA9  → USB-TTL RX
STM32 PA10 ← USB-TTL TX
STM32 GND  — USB-TTL GND

STM32 3.3V → OLED VCC
STM32 GND  — OLED GND
STM32 PB1  → OLED SCL
STM32 PB0  → OLED SDA
```

USB-TTL 使用 3.3 V 逻辑电平，开发板由 ST-Link 供电时，不连接 USB-TTL 的 VCC。

## 功能实现

### 三灯流水灯

- 使用 PA4、PA6、PA7 控制三颗 LED。
- LED 为低电平点亮。
- 运行状态下根据 `lamp_step_ms` 切换 `lamp_led`。
- 正向顺序为 `0 → 1 → 2 → 0`。
- 反向顺序为 `2 → 1 → 0 → 2`。
- 暂停时保持当前 `lamp_led`，恢复后按当前方向继续。

流水灯没有使用阻塞式 `HAL_Delay()`，而是通过 `HAL_GetTick()` 计算时间差。因此较长的切换间隔不会阻塞主循环。

### 按键控制与消抖

PA11 和 PA12 均配置为：

```text
下降沿触发
内部上拉
EXTI外部中断
```

中断回调只设置事件标志：

```c
key_run_event = 1U;
key_dir_event = 1U;
```

状态修改、消抖和 OLED/串口反馈均在主循环完成。

消抖流程如下：

1. 中断记录下降沿。
2. 主循环等待 20 ms。
3. 再次读取按键引脚真实电平。
4. 只有引脚仍为低电平时，才确认一次有效按下。

因此无效的短暂低电平不会改变运行状态。

### USART1与数据包接收

USART1参数：

```text
波特率：115200
数据位：8
校验位：None
停止位：1
硬件流控：Disable
```

程序使用 `HAL_UART_Receive_IT()` 一次接收完整的 6 字节结构体：

```c
typedef struct __attribute__((packed))
{
    uint8_t header;
    uint8_t run;
    uint8_t dir;
    uint16_t step_ms;
    uint8_t checksum;
} RxPacket;
```

`packed` 防止编译器在字段之间插入填充字节，使结构体大小严格等于 6 字节。STM32F103 使用小端字节顺序，因此 `STEP_L STEP_H` 可直接解析为 `uint16_t step_ms`。

接收完成回调只设置 `packet_ready`。主循环复制数据包、完成校验后再启动下一包接收，避免处理当前包时数据被下一包覆盖。

### 数据包格式

```text
AA RUN DIR STEP_L STEP_H CHECK
```

| 字段       | 字节数 | 含义            |
| -------- | --: | ------------- |
| `AA`     |   1 | 固定帧头          |
| `RUN`    |   1 | `00`暂停，`01`运行 |
| `DIR`    |   1 | `00`正向，`01`反向 |
| `STEP_L` |   1 | 切换间隔低字节       |
| `STEP_H` |   1 | 切换间隔高字节       |
| `CHECK`  |   1 | 前5字节累加后保留低8位  |

计算公式：

```text
CHECK = (AA + RUN + DIR + STEP_L + STEP_H) % 256
```

处理数据包时必须同时满足：

- 帧头为 `0xAA`；
- `RUN` 为 `0` 或 `1`；
- `DIR` 为 `0` 或 `1`；
- 间隔范围为 `100～2000 ms`；
- 接收到的 `CHECK` 等于重新计算的值。

只有全部条件成立后，才同时更新运行状态、方向和间隔。校验失败的包不会修改任何状态。

常用测试数据包：

| 状态            | 完整数据包               |
| ------------- | ------------------- |
| 运行、正向、300 ms  | `AA 01 00 2C 01 D8` |
| 暂停、正向、300 ms  | `AA 00 00 2C 01 D7` |
| 运行、反向、300 ms  | `AA 01 01 2C 01 D9` |
| 暂停、反向、1000 ms | `AA 00 01 E8 03 96` |
| 运行、反向、1000 ms | `AA 01 01 E8 03 97` |
| 运行、正向、100 ms  | `AA 01 00 64 00 0F` |
| 运行、正向、2000 ms | `AA 01 00 D0 07 82` |

串口助手发送时必须选择 HEX 模式，不添加换行。

### 软件I²C OLED

OLED 使用电控组提供的软件 I²C 驱动：

```text
SCL：PB1
SDA：PB0
```

驱动会在 `OLED_Init()` 中自行初始化 PB0 和 PB1，因此不需要在 CubeMX 中启用 I²C1 外设。

屏幕显示：

```text
STATE: running
DIR: forward
STEP:0500
LED: 1
```

暂停状态显示 `STATE: pausing`，反向状态显示 `DIR: backward`。

OLED 使用 `oled_dirty` 合并刷新请求。一次主循环内即使运行状态、方向和 LED 编号同时改变，也只在末尾刷新一次屏幕。字符串使用等长补空格，避免从较长文字切换到较短文字后残留旧字符。

当前驱动使用 ASCII 字符点阵，因此状态文字使用英文和数字，不显示中文。

### 串口中断反馈

状态发生以下变化时发送反馈：

- PA11改变运行/暂停状态；
- PA12改变方向；
- 合法串口数据包改变状态。

正常切换 LED 时不发送日志。

反馈通过 `HAL_UART_Transmit_IT()` 启动，格式为：

```text
STATE=pausing,DIR=forward,STEP=500,LED=2
```

字段说明：

- `STATE`：`pausing`或`running`；
- `DIR`：`forward`或`backward`；
- `STEP`：当前切换间隔，单位ms；
- `LED`：当前点亮的LED编号，范围1～3。

反馈字符串保存在全局缓冲区 `feedback_buffer` 中。发送期间不能修改该缓冲区，直到 `HAL_UART_TxCpltCallback()` 清除 `uart_tx_busy`。

若反馈请求发生在一次发送过程中，`feedback_pending` 保持为 1；当前发送结束后，再发送最新状态。

## 主要处理流程

主循环依次完成：

1. 检查并处理完整串口数据包；
2. 处理PA11运行/暂停事件；
3. 处理PA12方向事件；
4. 根据运行状态和间隔更新LED编号；
5. 输出三颗LED；
6. 如有需要，刷新OLED；
7. 如有需要，启动串口中断反馈。

中断回调不直接修改灯、OLED或发送反馈，只完成必要的接收与事件记录。

## 开发过程中遇到的问题（真的真的是我遇到的！！！让AI帮忙记录了下来）

### 1. CubeMX重新生成后用户代码丢失

最初部分LED代码位于 `USER CODE` 标记之外，重新生成工程后代码被清除。后来将用户代码移动到对应的 `USER CODE` 区域，避免再次丢失。

### 2. 按键接触不稳定

调试中曾出现按键偶尔无响应的问题。检查后确认存在接线未插紧和触点接触不稳定的情况。改进后使用 20 ms 后读取真实电平的方式消抖，而不是只设置固定时间间隔。

### 3. USART1与USART2选错

配置串口时一度打开了 USART2 页面。最终确认使用 USART1、PA9/PA10，并将硬件流控设为 Disable。

### 4. 数据包校验和修改错误

测试暂停包时只把 RUN 从 01 改成 00，却没有同步修改 CHECK。由于前5字节总和减1，校验字节也必须由 `D8` 改为 `D7`。程序正确拒绝了该错误数据包。

### 5. CLion与CubeMX文本编码不一致

CubeMX 重新生成代码后，中文注释曾出现乱码。主工程文件使用 GBK 编码；导入老师提供的 OLED 驱动时也需要注意与 CLion 的文件编码设置保持一致，避免中文注释乱码。

### 6. OLED文字残留

从 `backward` 切换到 `forward` 时，新文本少一个字符，最后一个旧字符仍保留在屏幕上。解决方法是让状态字符串等长，或覆盖完整固定宽度字段。

### 7. CMake目标名称不一致

重新生成工程后，CLion运行配置曾找不到 `assignment3.elf`。检查发现 CMake 目标名与运行配置不一致，统一工程目标名称并重新加载 CMake 后解决（到那个txt文件里面去改好，点reload）。

## 思考题

当流水灯切换间隔较长时，按键和串口是否会出现延迟？

本项目没有使用阻塞式 `HAL_Delay()` 等待完整切换周期，而是每轮主循环读取 `HAL_GetTick()` 并计算时间差。因此即使间隔为 2000 ms，按键和串口事件仍能被主循环及时处理。

OLED 软件 I²C 刷新本身是同步操作，但只在状态变化或需要刷新时执行，没有在每次主循环中重复刷新（多次状态变化时，以主循环为准，oled只刷新一次）。若后续加入更多同步外设，可以继续使用事件标志和分时处理，减少单个主循环周期内的耗时。
